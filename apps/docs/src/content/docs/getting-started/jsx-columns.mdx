## `field` instead of `id` + `accessor`

```tsx
<DataGrid.Column<Employee> field="name" header="Name" />
// same as
{ id: "name", header: "Name", accessor: (row) => row.name }
```

You can still pass `id` and `accessor` yourself (e.g. for computed values).

## The cell

A function child renders the cell:

```tsx
<DataGrid.Column<Employee> field="status" header="Status">
  {(row) => <StatusBadge status={row.status} />}
</DataGrid.Column>
```

Or use named parts when you need more than the cell:

| Part                          | Same as         |
| ----------------------------- | --------------- |
| `<DataGrid.Column.Cell>`      | `cell`          |
| `<DataGrid.Column.Header>`    | `headerCell`    |
| `<DataGrid.Column.Aggregate>` | `aggregateCell` |
| `<DataGrid.Column.Edit>`      | `editCell`      |

## Mixing with `columns`

Both can be used at once: the `columns` array comes first, then the JSX columns.

## Notes

- `<DataGrid.Column>` renders nothing by itself; the grid reads it.
- Columns without `field` or `accessor` are [display columns](/features/display-columns/) (actions, icons).
- The generic `<DataGrid.Column<Employee>>` gives typed `field` names and rows; it is optional.
