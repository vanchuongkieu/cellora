Vietnamese names are full of diacritics (`Nguyễn`, `Trần`, `Đỗ`), and nobody types them in a search box. The same goes for `García`, `Müller` or `Crème`. A table search that compares raw strings misses most of what people look for. Cellora matches without accents by default.

Type `nguyen`, `tran` or `lea` above.

## How it works

- Both the search text and each cell value are lower-cased and **folded**: Unicode NFD decomposition, combining marks stripped, `đ`/`Đ` mapped to `d`/`D` (they are letters, not marks, so NFD alone misses them).
- Typing with accents still works: `Nguyễn` is folded too, so it matches `nguyen` and `Nguyễn`.
- Column filters in the column menu use the same rule.
- It is on by default. `ignoreAccents={false}` restores exact matching.

```tsx
<DataGrid rows={rows} columns={columns} enableSearch />            // "nguyen" finds "Nguyễn"
<DataGrid rows={rows} columns={columns} enableSearch ignoreAccents={false} />
```

## Cost on large data

Folding only runs when the plain comparison fails and the text contains non-ASCII characters, so English data pays nothing. Folded strings are memoized (names and categories repeat). Measured on 1,000,000 rows × 3 accented columns: about 0.7 s for the first keystroke; the next keystrokes only re-filter the previous matches. Typing never blocks, because filtering runs in a deferred render.

## Use the same folding in your own code

The function is exported from `@cellora/core`:

```ts
import { foldAccents } from "@cellora/core"

foldAccents("Trần Thị Đào") // "Tran Thi Dao"
```

Useful for a custom `searchFilter`, for sorting keys, or for an API that receives the search text.

## Combine with custom rules

- `searchValue(row)` per column: search formatted text (a date as `"5 Mar 2024"`) instead of the raw value.
- `searchable: false`: keep ids out of the search.
- `searchFilter(row, term)`: your own matching (multi-word, `field:value`), still accent-folded if you call `foldAccents` yourself.

All options: [Search](/features/search/).

## FAQ

**Does sorting ignore accents too?**
Sorting uses a locale-aware collator with `sensitivity: "base"`, so `Đào` and `Dao` sort as equal and strings order naturally (`file2` before `file10`).

**Does this work for other languages?**
Yes: any language whose accents are Unicode combining marks (French, German, Spanish, Portuguese, Czech, …) folds the same way.
